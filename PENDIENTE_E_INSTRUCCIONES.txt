ARCADE PRO — LO QUE QUEDA POR HACER E CMS (/cms)
----------
· cms.php: entra en https://tu-dominio/cms. La primera visita pide crear la contraseña (hazlo nada más subirlo).
· Guarda los cambios en data/cms.sqlite (no está en git; la bloquea el .htaccess). Haz copia desde «💾 Copia».
· index.php aplica esos cambios encima de data/arcade.sqlite con cms_overlay(): borrar data/cms.sqlite = volver al
  catálogo original. Los juegos del catálogo no se pueden cambiar de identificador (rompería las URLs).
· El servidor necesita permiso de escritura en data/ (y en pwa/ para subir .html).

Rehacer en JS + emojis los grandes éxitos de móvil de la lista de referencia para la

IMPORTANTE AL GENERAR O SUBIR CAMBIOS
· Después de cualquier cambio ejecuta SIEMPRE: php herramientas/arcade.php todo
  (entre otras cosas pone ?v=<hash> en los .js/.css de todas las páginas; sin eso el navegador puede mezclar un HTML nuevo con un
  common.js viejo de su caché (pasa: no salen los sprites, ni la demo, error «Arcade.foe is not a function»).
· Sube SIEMPRE juntos pwa/common.js, pwa/common.css y los .html: si en el servidor queda un common.js viejo, falla igual.

JUEGOS EDUCATIVOS (o cualquier juego hecho aparte) — CÓMO AÑADIR MÁS
· Copia la carpeta del juego en educativos/<nombre>/ tal cual (no hace falta que use common.js).
· Añade una entrada a "sueltos" en herramientas/datos/educativos.json (id, app, asignatura: mates|lengua|logica|ingles,
  emoji, edades [mín, máx], idiomas, url, titulo es/en, desc es/en) y, si es una app nueva, otra a "apps".
  Asignaturas y tramos de edad nuevos: "asignaturas" y "edades" en el mismo archivo.
  Un juego arcade que también sirve como educativo: entrada en "arcade" (ref = id del juego).
· Regenera: php herramientas/arcade.php todo
· Colecciones y categorías: herramientas/datos/catalogo.json (o, sin tocar archivos, desde el CMS en /cms).

Criterios ya decididos:
· Si varios títulos comparten mecánica se fusionan en un juego (el campo "origin" lista todos los títulos).
· Nombres propios en español (y "title" en inglés), sin personajes ni marcas registradas.
· No se hacen: Boids (no es juego), Educational Game, Line Rider (sandbox), Legends of Runeterra (demasiado grande),
  Knife Hit (ya existe aparte como "Knife Emohit"), Meowdoku (= Emojidoku).
· Táctil SIN cruceta en pantalla; en TV, cruceta/cursor.

INSTRUCCIONES PARA CONTINUAR
----------------------------
Requisitos: solo PHP 7.4+ con pdo_sqlite y mbstring (la web y las herramientas). Nada de Python ni Node.
Los datos del catálogo están en JSON (herramientas/datos/) y la web lee SQLite (data/arcade.sqlite, que se genera).

1) Crear un juego nuevo
   · Copiar un juego parecido de herramientas/src/ como plantilla (p. ej. torreta.js = toque simple,
     esquiva.js = arrastrar, gemas.js = tablero, tirachinas.js = física con "// @phys").
   · Estructura obligatoria de cada src/<id>.js:
       // Título|#colorDeTema
       // @phys          ← solo si usa Arcade.Phys (phys.js)
       (function () {
         const { ri, rand, clamp, pick, shuffle } = Arcade;
         Arcade.game({
           /*THEME*/ home: 'indexpro.html', tag: '…', deco: [6 emojis], font: 'round|serif|mono|impact|comic|wide|fancy',
           bg: ['#claro', '#oscuro'], music: { mode: 'major|minor|dorian|lydian|mixo|harm|phryg', bpm, wave, style, root },
           voice: {…}, ambient: {…opcional},
           en: { title, tag, help, tvHelp, dict: { 'texto ES dibujado en canvas': 'EN' } },
           tvHelp: '…', tv: false | { mode: 'tap'|'swipe'|'drag', targets: (g) => [{x,y,w,h}] }  (sin tv = teclas),
           id, title, emoji, color, origin, help,
           lives: 3 (0 = sin vidas), levels: 0 (infinito), cap: 20–30,
           setup(g) {…g.s = estado…}, layout(g) {…recalcular geometría…},
           down/move/up/tap/swipe(g, p|dir), key(g, k, down), hover(g,x,y), update(g, dt), draw(g, ctx)
         });
       })();
   · API útil del motor: g.W g.H g.top g.bot g.lv (nivel con tope) g.level g.rt; g.addScore(n,x,y); g.win(estrellas?)
     (sin argumento calcula estrellas por vidas perdidas); g.die() → false si se acabó la partida; g.message(txt,t,sub);
     g.float, g.burst, g.ring, g.flash, g.shake, g.confetti, g.scenery; Arcade.emoji(ctx,e,x,y,size,{rot,alpha,flip,sx,sy});
     Arcade.txt(ctx,txt,x,y,size,color,align,peso,trazo); Arcade.rr (rect redondeado); Arcade.sfx.{coin,pop,hit,boom,win,
     lose,tick,move,up,bad,whoosh,combo(n)}; Arcade.tone(f,dur,onda,vol,slide); Arcade.T('es','en'); Arcade.lang.
   · Todo texto que se dibuja con Arcade.txt en español debe tener su traducción en en.dict (se traduce por fragmentos).
   · Protagonista: dibújalo con g.face() (cara que cambia sola; g.mood('scared') etc. para forzar). Enemigos: usa
     Arcade.FOES / Arcade.foe(n). Lo que se mueva, dibújalo con Arcade.emojiTo(ctx, e, x, y, tam, dx, dy) y, si el emoji
     es nuevo, añade hacia dónde mira en Arcade.FACING (common.js). El pad virtual 🎮 sale solo si el juego tiene key()
     o tv.targets (pad: false para quitarlo).
   · Demo: añade demo(g) que devuelva pasos ({ tap }, { drag }, { swipe }, { hold }, { key }, { wait }, con say/after);
     ver pwa/README.md («Demo automática»). Pruébala con el botón 👀 Ver demo: debería jugar con sentido y explicar
     la mecánica con 1–3 frases cortas.
   · Para reiniciar nivel tras perder vida: setTimeout(() => { if (g.state==='play' && g.die()) Arcade.current.def.setup(g); }, 1200).

2) Registrar y construir
   · Añade una línea a herramientas/datos/juegos.json:
       {"id":"<id>","coleccion":"pro","categoria":"<categoría>","control":"Tocar","tv":"cursor",
        "desc":{"es":"…","en":"…"},"version":"<versión nueva>"}
     (coleccion: main | pro | mesa; tv: false | "cursor" | "cruceta"; el orden del archivo es el de las portadas).
     Opcional: "tag":{"es","en"}, "emoji" u "origen" para que la portada muestre otra cosa que el juego.
   · Sube "version" en herramientas/datos/catalogo.json para que la PWA se actualice en los móviles.
   · php herramientas/arcade.php todo → comprueba los JSON, crea pwa/<id>.html, pwa/games.js, las huellas ?v=,
     data/arcade.sqlite (la web PHP lee de ahí) y autonomos/. Con «comprobar» solo revisa, sin escribir.
   · Título, emoji, color, origen, ayuda es/en, vidas y niveles salen del propio src/<id>.js (Arcade.game({…})):
     no se repiten en los JSON.

3) Probar
   · Abre la web con: php -S 127.0.0.1:8080 -t . herramientas/router.php
   · En el navegador: /<id> y /<id>/en, la consola sin errores, la demo (👀 Ver demo), el modo TV (?tv=1) y las
     capturas en vertical (390×780) y en TV (960×540).

4) Publicar
   · Se trabaja directamente en la rama main (sin ramas).
   · Solo hosting con PHP + Apache (ya no hay versión estática para GitHub Pages): sube todo el repositorio
     (index.php, cms.php, .htaccess, data/, pwa/, educativos/, autonomos/). Necesita mod_rewrite y pdo_sqlite. Si va en una subcarpeta y las URLs fallan, activa RewriteBase en .htaccess.
     Después, da de alta https://tudominio/sitemap.xml en Google Search Console.
